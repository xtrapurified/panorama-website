## Platform

web

## Users

Clients commissioning films: institutions, foundations, NGOs and brands in the UAE, Europe and Serbia who are deciding whether to hire Panorama Films for a film. They arrive to judge the work, see who the studio has made films for, and understand what the studio can do. Success is an enquiry through the contact form on panoramafilms.tv.

## Product Purpose

The website is the portfolio and front door of Panorama Films, an independent creative storytelling studio in Belgrade, Serbia, available worldwide. It shows the films, the studio and its approach, and turns a convinced visitor into a commissioning enquiry.

## Positioning

A full-service studio that takes a film from first question to final frame: research, writing, shooting and editing under one creative direction, by a small team (Andrija Kovač, Creative Director; Mina Strugar, Producer; Marija Kovačina, Editorial Director) working with collaborators.

## SEO (2026-10-20)

- **One page per project, and it is the real site.** Every published project has its own address, `/work/<slug>/`, the slug made from its title (`/work/what-does-the-future-hold/`, all seasons). Cloudflare runs `functions/work/[[path]].js` for `/work/*`: it serves `index.html` (which carries `<base href="/">` itself since 2026-10-22, so media paths stay at the root after a project sets its `/work/` address; before, opening a project from the homepage broke its photos and film stills) with that project's title ("Title — Client | Panorama Films"), description (logline + intro), canonical, share image and structured data (BreadcrumbList, CreativeWork; no VideoObject, since Google requires an upload date we do not have) in the head, plus `<base href="/">` so the page's relative paths work; the page's script then opens the project exactly as on the homepage. Opening a project anywhere on the site sets the address to `/work/<slug>/` (and the tab title); Close, Esc, swipe or Back return to `/`. Old `#slug` links (`#What-Does-The-Future-Hold-Season-3`, `#DUBAI-TGR` …) open the project and switch to the new address. Unknown slugs go to the homepage; a wrong case or missing slash is redirected to the exact address.
- **No build step.** The function and `functions/sitemap.xml.js` read the projects straight from `index.html` through `lib/site.js` (F, LIST, INDEX, DRAFTS, HIDDEN, pjdata, crdata), so adding, renaming, hiding or reordering a project needs nothing else. The sitemap is built on each request (homepage + every published project). The slug rule is the same in `lib/site.js` and in the page (`slugify`); renaming a project changes its address, so add the old address to `_redirects` when renaming a published project.
- **Share images:** `media/og/<slug>.jpg` (1200×630) from each project's still; run `python3 tools/seo/og.py` when a project is new. Without one, the WebP still is used.
- **Homepage:** title "Panorama Films - Documentaries, campaigns and brand films" (Andrija, 2026-10-21; it is what Google shows as the headline), description for UAE institutions and worldwide, og:image `media/og/home.jpg` (the child holding a hand at sunset, showreel V4 at 0:59.7, chosen by Andrija 2026-10-21 from ten frames; `og.py` leaves it alone), JSON-LD (WebSite, Organization with areaServed UAE / Serbia / Worldwide and sameAs Instagram / Vimeo / YouTube, the three core people as Person). Project cards link to `/work/<slug>/` (a click still opens the project in place). Film stills carry the title as alt text.

## Product Principles

1. The films carry the site. Every decision should help a commissioning client see the work quickly and in good quality.
2. One studio, first question to final frame: show the full research-to-edit capability through real projects, not service lists.
3. Truth over polish: real titles, clients, years and roles from panoramafilms.tv, in its order, or nothing.

Saving from the live addresses (panoramafilms.tv, www.panoramafilms.tv, panorama.mov, www.panorama.mov, panorama-website.pages.dev) commits to `main`, so the change is live about a minute later (Andrija, 2026-10-16: a save is his approval); saving from the dev preview commits to `dev`. `GITHUB_BRANCH` overrides both. Before committing it checks the list on GitHub: if a photo was added or removed since the page loaded the list, it refuses and asks for a reload, so two saves can never overwrite each other. Secrets `GITHUB_TOKEN` (fine-grained, this repo only, Contents read and write, set 2026-10-16) and `SLIDESHOW_PASSWORD` are set on Production only (not Preview), so saving works on panoramafilms.tv/slideshow/; the dev address says saving isn't switched on.
